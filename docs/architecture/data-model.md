# Data Model (Firestore)

Cloud Firestore, project `taal-yatra` (since 1.2.0, [ADR-0009](adr/0009-firestore-data-adapter.md)).
`core/backends/fake/fake-db.json` stays the source of truth: `npm run seed:firestore` copies it
into Firestore, and development, unit tests and the main e2e suite read it directly.

## Conventions

- Firestore paths mirror the `ApiEndpoint` enum. Two segments are a document; one segment is a
  collection, read with `orderBy('order')`.
- List sections stored as one document use the reserved key `_items`, not `items`, because
  `home/experiences` and `home/faq` already have a real `items` field.
- `site`, `home` and `pages` are each read whole, independently, the first time one of their
  documents is needed (ADR-0009, ADR-0011). Keep them small.
- **One source per entity** (ADR-0011): videos, team members, show formats and contact details
  are stored once and reach every page through a cached shared service (`cacheLatest`).
- List item documents are numbered by position (`001`, `002`, …). The adapter removes `order`
  from bodies.
- The adapter stamps `createdAt: serverTimestamp()` on every created document.
- Image paths point at files in `public/images`. Photos are WebP (since 1.5.0); the older JPEGs
  stay, so data seeded before a release keeps rendering. **Since 1.7.0, `IImage.src` can also be** an
  uploaded image, `[c_crop,x_…,y_…,w_…,h_…/]v…/<id>`, or a full URL such as a YouTube thumbnail.
- **Collections in drafts (1.7.0):** `drafts/gallery`, `drafts/team`, `drafts/showFormats` and `drafts/videos`
  hold `{ path, content: { _items: [...] }, savedAt }`. Publishing expands the list into numbered documents
  with `order` and deletes unused numbers. Limits, enforced by rules through the highest id: gallery 60, team
  24, shows 20, videos 60.
- **Since 1.6.0, Firestore is the source of truth for live content**: the owner edits it.
  `seed:firestore` creates missing documents only (`--overwrite` replaces after listing), and
  `export:firestore` backs the content up. `fake-db.json` stays the fixture for development
  and e2e.
- `site/config.promotion` has `live`, `startsOn` and `endsOn` (YYYY-MM-DD, Pune time); missing
  means on with no dates.
- DTO interfaces (`i-*.ts`) describe stored shapes; model classes add behaviour.
- **Optional parts of `site/config` degrade item by item.** Only brand, contact and year are
  required. Missing `labels` become empty, so "Call us" falls back to the number, the copyable
  address to plain text, and video cards to their titles. A missing `credit` hides the credit, and
  missing `socials` or `promotion` show none, and a missing or empty `seo` entry keeps the page's
  default title and description. One absent field never blanks a section.
- `firestore.rules` denies by default and is tested (`npm run test:rules`). Visitors can only read content, and
  only the admin may change it, with the shape the site renders; `site/theme` accepts only its listed fields, colours as
  `#rrggbb` and the rest from fixed lists, and the site ignores a stored theme that fails the contrast check (2.2.0);
  `savedThemes/{uuid}` are read and written by whoever sees the Theme page, and read and restored (not deleted) by
  Backups; the 20-theme limit and distinct names are the page's, since rules can't count documents (2.9.0);
  `site/visibility` may also hold `folded`, one of `never`,
  `phone`, `desktop`, `always` per foldable section (1.10.0) (the editable `home` sections are listed in
  `EDITABLE_HOME_SECTIONS`; `drumCircle` joined them in 1.9.0, and every other section but `assistant` in 2.10.0, each on its editor page in `homePages()`); `pages/{videos, team, shows, achievements}` are updatable since 2.11.0 the same way (`innerPages()`, keys kept, the heading's limits checked), never `pages/admin`; `proposals` is create-only for visitors, with exact keys, length limits from `PROPOSAL_MAX_LENGTH`, a required email (since 1.8.1), and
  `createdAt == request.time`; the admin reads and deletes them and may change only `status` and `statusAt` (1.13.0). `visits`
  accept only a listed page and device with the server's time; `visitDays` are admin create-only.
